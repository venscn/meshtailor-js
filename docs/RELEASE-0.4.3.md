# MeshTailor-JS v0.4.3 — 每岛独立播放与尾段接力

## 行为

默认播放方式改为「逐岛接力」。一岛独立完成分离、转向、铰链展平、UV 形变和移入 Atlas；它完成 85% 时下一岛才启动。仅相邻两岛的尾段 / 开头重叠，不会让全部岛共享同一个局部进度。「严格逐岛」则等到前岛 100% 再启动下一岛。

范围仍可选择单个、多选、全部。全部只代表将全部有效岛纳入队列，不代表同时启动。等待岛保持源 3D，已完成岛精确留在目标 UV，最终导出的 UV 没有因动画调度被更改。

### 例：三岛，每岛 12 秒，默认 85% 接力

| 岛 | 开始时刻 | 结束时刻 |
|---|---:|---:|
| 第一岛 | 0.0 秒 | 12.0 秒 |
| 第二岛 | 10.2 秒 | 22.2 秒 |
| 第三岛 | 20.4 秒 | 32.4 秒 |

前岛 90% 时后岛只到 5%；不会再次出现所有岛相同进度一起铺开的效果。每个岛仍得到完整的 12 秒生命周期。严格串行时上述总时长为 36 秒。

## 调度公式和接口

`packages/uv/src/unfold-schedule.ts` 是唯一的岛时钟实现。令实际有效选择数为 N，每岛时长为 D，交接点为 h：

```text
start(i) = i × h × D
end(i) = start(i) + D
total = N > 0 ? D × [1 + (N − 1) × h] : 0
local(i, t) = clamp((t − start(i)) / D, 0, 1)
```

默认 h=0.85；允许 0.75–1.00。严格串行固定 h=1。这个范围保证最多两岛活动。N 使用实际选择，不用总网格岛数、不保留无效或重复 ID 的空槽。顺序采用岛列表 / 多选顺序。

`UnfoldOptions` 新增 `handoff?: number`、`holdNet?: boolean`。`order='relay'` 为新默认，`sequential` 保留；旧 `together` 输入迁移为 relay，不再悄悄落回全体同步模式。UI 已移除同时展开选项。

几何位置、铰链剩余角度、铰链 / 临时断边显示、每岛列表进度、阶段按钮和两套播放器均使用同一份 local/global 映射。反向播放读取同一个时间轴，顺序反向，不积累变换误差。源 / 目标位置缓冲不可变。

## 进度、检查和跳转

界面显示活动岛编号及局部 UV 完成度、已完成 / 等待数量、真实总时长和剩余时间；反向时相应显示已折回 / 待折回。进度条是队列总进度，不是所有岛共同的局部进度。

阶段按钮定位到当前岛。点击队列上一个 / 下一个岛后，检查对象固定为所选的队列成员，避免重叠期按阶段按钮误跳回前岛。播放恢复后继续按队列推进。支持选择单岛研究、多选比较、全部播放，且不会修改 UV 目标。

在多岛网格上，活动岛标签优先进入有限的 DOM 标签预算；完整岛列表仍可在 Studio 分页查看。相机默认自由；本版不按当前岛强行移动、缩放或锁定相机。

## 对「后半段等很久」的处理

1. 删除了默认全体同进度启动这一调度路径。
2. 原几何关键帧 70–80% 的固定平面网停留默认关闭。`holdNet=true` 可以显式恢复教学停留；也可点击「检查平面网」暂停。跳过这一段是连续的，因为两端是相同的刚性平面网，铰链数学和 UV 终点不变。
3. 去掉每帧最多只计入 100ms 的截断，按实际可见播放时间累计，避免低帧率被偷偷变成更长的动画；隐藏页签重置时间戳，不补播隐藏期间的时间。
4. 去掉循环末尾固定 650ms 等待。最后一岛完成就是本轮终点，不增加空队列槽位。

岛多时总播放仍会更长，这是逐岛完整预览的真实成本；UI 明确显示时长，可以减少每岛时长、选择部分岛或跳队列检查。低帧率仍会减少可见中间帧，调度修复不是任意复杂模型的帧率保证。已经平坦或已接近目标形状的岛可能某些阶段变化很小，不凭空制造折叠。

## 验证与限制

新增 22 项共享调度回归、28 项真实浏览器 relay 回归。真实浏览器使用默认三折角带，前向 / 反向完整播放、滑杆交接点、严格串行、多选顺序、阶段定位、固定停留开关、相机拖动都经过实际操作；逐帧检查最多两岛活动，检查等待 / 完成岛的真实位置缓冲。

原有 17 项铰链边长 / 共享端点 / 连续性回归改成按每岛局部时刻检查，不能继续假设整个模型处于同一个阶段。39 项自由相机、24 项原生展开渲染、21 项离线实验页等回归也已运行。详细记录与未验证项见 `VALIDATION.md`。

没有声称完整 React/Vite 主界面联调通过。npm registry 请求失败于 EAI_AGAIN，完整 build 实际失败于 vite: not found。通过的是共用生产模块的离线 UI、真实 WebGL2 和 classic browser Worker，以及严格编译的核心模块；两项原生 module Worker 检查显式跳过。没有重跑实际 Flight Helmet 资产、FBXLoader、Safari/macOS/Windows 或硬件 GPU 测试。
