# v0.4.4 — 跳过每个岛没有实际变化的动画区间

## 本次修复

v0.4.3 虽然让岛逐个接力、去掉默认平面网停留，但仍给每个岛固定分配“分离、转向、铰链、UV 形变、排布”的时间。已平整的岛可能没有铰链动作；刚性展开后的形状可能已与目标 UV 一致。原先这些阶段仍消耗时长，造成画面长时间不动。

现在默认开启 **自动跳过无变化区间**。每个岛拥有独立的有效动作时间线，没变化的区间被压缩为一个时间点。删除的时间直接从岛时长、队列时长中扣除，不重新摊给其他动作。原来一个动作的播放速度不会因删掉其他阶段而降低。

当前“每岛基准时长（跳过前）”仍默认为 12 秒。它是完整参考流程的时长，不是强制每岛播放 12 秒。实际六岛立方体的回归中，各岛省掉了不需要的铰链和 UV 形变阶段，每岛实际 4.8 秒；85% 接力总时长从 63.0 秒变为 25.2 秒。这不是所有模型的固定加速比例。

## 判定哪些区间可以跳过

| 阶段 | 判定依据 |
|---|---|
| 分离 | 当前源中心与实际陈列位置之间的位移。 |
| 转向 | 每个面角相对旋转轴的距离以及实际旋转角；不是观察轮廓是否相似。 |
| 铰链 | 真实非零关节旋转、从根面传播的活动时间范围、展开过程中重新居中的位移。完全不动的铰链阶段、波次开始前/结束后的静止段可被省去。 |
| UV 形变 | 刚性平面网与尚未装箱的目标 UV 形状之间的最大逐角位移。 |
| 排布 | 当前位置、目标位置和统一缩放造成的实际逐角位移。 |
| 直接/分段插值对照路径 | 各自实际插值段的最大逐角位移；不能只比较整条路径的首尾。 |

特别避免“起点等于终点，所以整个过程都没有动作”这种误判。分离后又回到同一位置的过程必须保留；铰链过程依据内部关节的活动范围判断，即使总位移抵消，也保守保留真实的中间动作。

不是逐帧截图比较，也不根据相机朝向、可见性或遮挡删时间。切换相机不会改变动画速度或时间线。默认相对容差为岛尺寸的 `1e-6`，再加归一化世界坐标下的 `1e-8` 绝对容差。容差内的微小位移会视作静止；精确的源网格和目标 UV 端点仍直接使用原始缓冲。调大容差可能省略可见的细微运动，应谨慎使用。

几何分析为线性遍历并缓存。仅切换网格、UV、选择、路径、分离距离、铰链波次或判定选项时重算，不会每帧重算。90,112 三角形程序机械件的原始 UV 输入，本轮单独分析耗时约 295 毫秒；不包含 UV 求解和构建铰链的时间，也不是飞行头盔实测。

## 接力、进度与检查方式

接力点作用于上一岛压缩后的有效播放时间。由于每岛时长不再相同，实际重叠为：

```text
overlap = min(前岛实际时长, 后岛实际时长) × (1 − 接力阈值)
后岛开始 = 前岛结束 − overlap
```

因此，默认 85% 表示下一岛不早于前岛有效进度 85% 启动；后岛特别短时会更晚启动，避免越过前岛先结束或导致第三岛提前加入。最多相邻两岛活动。严格逐岛模式没有重叠。全岛无动作时实际时长可以为零，不建立假的等待时段，循环请求也不会陷入无动作空转。

几何、铰链剩余角度、临时断边、活动岛计数、进度条、阶段按钮及正反向播放共用同一映射。点击已跳过的阶段，会定位到压缩后的同一瞬间，而不是重新插入停顿。

Studio 左侧与离线页新增：

- 默认开启的“自动跳过无变化区间”，关闭后可对照原固定时长。
- 原队列时长、实际时长、缩短时间；当前岛省略的阶段。
- 相对容差设置；Studio 的岛列表显示各岛实际时长，悬浮可查看跳过项目。

用户主动开启的“平面网额外停留”仍保留，自动跳过不会覆盖这个有意的观察请求。默认关闭。播放期间的自由相机、单选/多选/全部、反向、循环与队列导航均保留。

## 范围与验证

本版不修改 UV 求解器、装箱算法、裁切拓扑、目标 UV、导出格式或相机控制策略。它只删除动画中没有实际变化的时间，不会让仍有运动的岛强行瞬间到达目标。

新增测试命令：

```bash
npm run test:motion-time
npm run test:motion
npm run lab:build
npm run test:motion:browser
```

依赖轻量的测试仍需要本地或全局 TypeScript，浏览器测试需要 Chrome/Chromium/Edge。完整验证结果和环境限制见 `VALIDATION.md`。完整 React/Vite 主界面构建、真实 FBXLoader、真实 Flight Helmet、macOS/Windows/Safari 和硬件 GPU 本轮未验证；已通过的浏览器测试是离线页及其共用的生产模块，不冒充完整主界面联调。
