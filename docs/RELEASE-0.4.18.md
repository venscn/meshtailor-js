# v0.4.18 · 通用空间分组剥展与有预算的轮廓填空

基于已发布 `v0.4.17 → 0a26f0e` 的原仓库继续维护，没有重建历史、移动旧 tag，也没有改名导入旧错误模型。新算法针对几何特征，不按 Corset、头盔、齿轮名称或源岛编号选择处理分支。

## 1. 分组不是展开：真正分成两层

```text
源拓扑与受保护的边界
  → 真实连通块；较大的平面特征单独分组
  → 对较大的环绕曲面，依据主法向两侧支持量形成平衡朝向面板
  → 每组尝试开缝、投影初始形态与自由边界展开
  → 验证失败后才反馈增加组内切线／二分
  → 可选借用有效原 UV 子形状（有独立计数）
  → 全部真实面和 UV 有效性检查
  → 面积归一、排布及可选填空
```

### 空间组先保持粗粒度

从原始几何连通分量开始，不把每处法向改变都当成独立区域。占整体表面积足够大的连续近共面面板与侧壁区分，保留平面轮廓的齿形、孔洞、凹口。

对于占总表面积至少4%、至少32面的非平面组，如果主法向轴两侧均有足够面积支持，则从相反朝向的两点做一次平衡的连通测地分区。每个子块至少占父块25%、至少16面。不是给所有附件做重复朝向分箱，更不按细分三角形数量预先切碎。

“较大面板分组”可关闭，面积阈值可调。分组边界进入真实裁切保护集合，后续普通缝合不能悄悄把两个受保护的组重新缝起来。组 ID、面归属、失败原因及最终岛数随 Worker 快照传递，重排/填空保留这些关系。

### 投影只是候选，不是通用最终答案

使用按表面积加权的局部坐标轴，尝试多个投影方向。只有自身没有翻面/重叠的投影才可作为直接平面结果或自由边界优化初值。环带/圆柱的已有解析展开仍是可选候选；自由曲面走 LSCM/ARAP。

圆周固定的 Tutte 只允许作为某些自由边界迭代的数值初始化，不是默认最终回退。组内所有方法失败后再增加必要切缝，不把整个模型统一映射成圆盘。圆盘本体与圆柱侧壁分别可能自然得到圆形与矩形；形状应对应实际几何，不能简单禁止所有圆形/方形。

### 防止“局部不翻，整体仍重叠”

此前 ARAP 回溯主要看能量和局部面朝向，边界可能绕到另一段边界上，直到最终检查才被发现并触发大量拆分。现在每次候选步还检查非相邻边界的交叉/接触；拒绝该步、减小步长。最终仍执行全部实际三角形的交叠检查。边界防护不是三维动画的连续碰撞检测。

真实头盔还暴露了一个“构形角度尚可，但局部面积压到接近零”的 LSCM 反例。新增相对于整岛平均 UV/3D 面积比的局部密度门槛（本路径最小1e-3、最大200），先尝试受保护的自由边界修复，失败才明确反馈切线。固定反例在 `examples/regression/collapsed-area-chart.json`，没有降低全图质量阈值放过它。

### 源 UV 提示与通用几何算法分开报告

默认允许在整个组求解失败后，利用有效的原 UV 子区域边界救援；只修复无效子区域。它不是“完全抛弃原 UV”的算法，也不把源子岛数量当作几何分组数。

关闭该选项可以检验纯几何分组/求解。两份真实模型开关源提示得到相同的空间组，最终岛数不同。额外的合成通用测试同时关闭源提示和结构模板，验证弯曲片、扭转带、马鞍、非对称曲面及带孔齿面不会依赖特定模型模板才能工作。

## 2. 实际结果及质量边界

| 正确模型 | 全部面数 | 原几何连通块 | 新空间组 | 默认最终岛 | 关闭源提示最终岛 |
|---|---:|---:|---:|---:|---:|
| Corset | 18,324 | 75 | 81 | 93 | 89 |
| FlightHelmet | 94,722 | 85 | 95 | 176 | 251 |

默认分别使用12、109个有效源子形状救援。关闭源提示后的头盔仍会产生更多岛，这个代价没有隐藏。前一轮探索中的数百个碎片结果没有作为默认输出交付。上述分组不是对人体、衣物或零件含义的语义识别，也不证明最少岛数或最适合手绘的普遍结果。

Low 齿轮在同时关闭源提示和模板时得到6组/6岛；两个主要平面保留齿形与中心孔，并验证其最终UV与源平面是相似变换。其余侧壁允许为条带，不会为了让所有岛看起来“像齿轮”而扭曲侧壁。

所有真实结果保留源位置和面顺序。生产 UV 检查、OBJ 重读和额外独立 GEOS/Shapely 三角形求交均通过；在1e-14 UV²面积阈值上无正面积重叠。原文件与导出哈希在 `validation/v0.4.18/qa-*.json`。Python仅作额外QA，不是JS运行依赖。

## 3. 填空：解开共同尺度与相对清晰度，显示真实停止原因

### 两种上限不再混用

- `fillCommonGainLimit`：整套布局共同增加面积的上限，默认4（1–16）。
- `fillMaxAreaGain`：差异化放大/岛间平均密度限制，原1.6仍保留。

共同放大不应因“不能让一个岛比另一个清晰太多”而被同一阈值挡住。每个岛仍不低于本次开始时的面积，只有完整可行布局才提交。

### 不把凹口当成实心包围盒

新轮廓栅格路径从真实 UV 三角面的边界生成保守占用网格，轮廓内部用扫描线填充，孔洞/凹口为空。边界身份歧义或非流形时回退到保守逐三角形栅格；不将不同边界随意舍入焊接。23项测试与三角形覆盖对照，包含孔、窄缝、凹口及旋转。

先尝试原来四个直角方向，必要时再尝试额外方向，避免每次都支付全方向代价；默认角步长45°，可选15°/30°/45°/90°。有界的前缀重排可以挪动之前锁定的大岛，寻找仅处理小岛无法获得的空位。没有剪切、镜像或分别拉伸U/V。

### 停止原因必须可核对

报告新增实际尝试岛数、未尝试岛ID、完整轮数、前缀重排次数及接受数、共同增益、剩余空网格连通区域。网格包含边距和保守离散化，**不能用空格比例反算真实纹理占用率**；有效占用率仍由最终三角形面积计算。

时间预算在搜索轮询点检查，可能有一个正在进行的操作造成超时幅度；搜索后的全图验证也另需时间。预算停止不等于迭代完所有岛，更不等于全局已填满。

## 4. 新分组结果的精排实测

以下是新形状的单次真实测量，不是同版型与旧算法的纯速度对照。

| 模型 | 通用剥展普通排布 | 第一轮精排后 | 真实岛数 |
|---|---:|---:|---:|
| Corset | 58.19% | 74.72% | 93→93 |
| FlightHelmet | 54.27% | 60.40% | 176→176 |

第一轮：512格、60秒搜索、16轮上限、2000次上限、45°、4次前缀重排、共同面积上限4、相对密度上限1.6。人台9轮后在当前步长/方向/约束下无改进，含验证约41.47秒；头盔约83.25秒（含验证）在时间预算停止，只完成1个完整扫描。不是默认15秒运行时间承诺。

头盔再从60.40%的当前结果以1024格、90秒继续，得到62.95%，没有改变176岛或缩小面。该次只尝试55/176个岛、完成0个整轮，121岛未尝试，明确是时间预算停止；含验证约120.02秒。更细网格可能找到窄空间，也可能更慢，不能声称红框所有空白均已解决。

特别保留了 **相同旧版型、相同30秒预算** 对照：人台旧79.8553%/新79.8337%，头盔旧59.4802%/新59.3251%。这是近似持平略低的单次结果，不是普遍提速/提升认证。新自由度与诊断已实现，但在短预算下不保证更好的局部搜索。见 `comparison/` 原始记录，未只挑有提升的结果。

## 5. 入口与参数

**模型 → 载入模型 · 自动处理流程 → 通用分组剥展**，然后重新加载或按流程重跑。该预设带填空；用户浏览器里的旧流程不会被覆盖。

独立入口：**UV → 通用分组剥展 · 空间组与组内切缝**。可开关有效源形状提示、较大相反朝向面板，调面积门槛。独立剥展后需要填空时再按“填补空白”。只重排保留空间组，显式源UV检查不自动改组。

填空使用当前完整snapshot，不从原始UV重来；原样检查用来打开交付OBJ而不重新生成。面积顺序、倍速、到达渐隐统一动画时钟、自由相机、框选、两级选面、播放透明上下文没有被新算法替换。新UV仍需要重绘/烘焙旧贴图。

```bash
npm run test:peel
npm run test:peel:real -- --out validation/local-peel
npm run test:peel:real -- --geometry-only --out validation/local-peel-no-source
node scripts/peel-fill-real.mjs --input validation/local-peel --out validation/local-fill --seconds 60
npm run lab:build
npm run test:peel:browser
```

固定夹具解码器仅接受哈希锁定的两份静态模型，不是通用 Three.GLTFLoader 替代。完整 Studio 通用导入仍走原入口。

## 6. 验证范围与研究边界

见 `docs/VALIDATION.md` 与 `validation/v0.4.18/README.md`。**完整 React/Vite 构建未通过**，npm DNS失败、build缺Vite、全量类型检查缺Node类型。真实浏览器测试是离线页的生产 Worker/WebGL，在Chromium软件渲染执行；拍摄大模型截图时关闭了叠层诊断，不作为大模型叠层性能认证。

方法背景仍是几何参数化与局部/全局ARAP的通用目标，不等同于这些库的实现：CGAL Surface Mesh Parameterization（https://doc.cgal.org/latest/Surface_mesh_parameterization/index.html），libigl Tutorial（https://libigl.github.io/tutorial/）。本项目为独立TS实现，未加入官方MeshTailor权重、学习语义模型或ZBrush代码。可读轮廓、切缝数、形变、填充率没有单一无代价最优解；本版没有引入自动反复切小岛去刷占用率。
