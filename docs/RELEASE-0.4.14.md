# v0.4.14 · 可配置载入流程与仅播放期间的当前岛突出

从 `v0.4.13 / a9317be` 的现有 Git 历史继续维护。没有改动 UV 参数化、缝合、精排搜索策略、铰链路径或模型数据。改变的是**自动步骤的编排、执行可见性与动画显示生命周期**。正确的人台/头盔哈希夹具仍包含在工程中。

## 1. 以前点击人台 / 头盔，实际做了什么

点击在线模型按钮时，主 Studio 先获取模型、读取几何与逐角 UV、保留材质身份并执行导入拓扑处理。默认位置焊接仍为 Boundary，参数仍在导入设置中。网络读取和解析状态显示在流程面板的输入栏；该时间不冒充下方 UV Worker 阶段的时间。

对于人台、头盔这类拥有完整原 UV 的模型，默认进入 `source-atlas`：

```text
读取 / 解析 / 导入拓扑
  → 检查几何与任务配置
  → 提取原 UV 岛，审计原 UV
  → 验证现有岛，局部修复无效原岛
  → 尝试通过质量检查的共享边缝合
  → 按 3D 表面积归一、大岛优先排布
  → [填补空白：旧版及“标准整理”默认不执行]
  → 建立同一份 3D / UV 对应与铰链数据
  → 面积与空间邻居统计，返回完整结果
```

并没有先偷偷按 baseline 重新切整件模型。没有完整原 UV 时，“自动”改走几何分区与参数化；这是明确的条件分支，面板里不适用的步骤标为跳过。

## 2. 新面板：模型 → 载入模型 · 自动处理流程

顶栏有“流程 / 处理流程”入口；面板在模型工具页顶部。既显示下一次载入计划，也显示当前任务实际日志，不再将两者混用。

| 预设 | 下次载入行为 |
|---|---|
| 标准整理（初始默认） | 自动选择原 UV 整理或生成，允许局部修复与缝合，不精排填空 |
| 整理＋填空 | 同上，排布后执行一次显式轮廓精排，再建立动画对应 |
| 原样检查 | 只检查并显示源 UV，不修复、不缝合、不排布、不填空；无完整原 UV 时明确报错 |

可单独选择 UV 来源、是否允许修复无效原岛、是否尝试缝合、是否自动填空；填空搜索预算默认15秒、最多8轮，可在流程面板修改。旋转、padding、分辨率、面积增益等更细选项继续使用 UV 工具页现有配置；执行报告保存的是实际解析后的全部选项。

自动填空本版使用既有的“大岛优先”模式；不在普通排布里暗中再调用一次精排，也不自动开启“大岛恢复旧切缝”实验。需要该实验、其他精排模式或对现有结果继续多轮填空，仍使用独立的“填补空白”操作。

### 保存与生效时机

修改保存在本浏览器的 `meshtailor.load-pipeline.v1`。下一次选择在线模型、复杂样例或本地导入时生效；不会因为改了一个勾选就丢掉当前结果，也不会改写正在运行的任务。

“按此流程重跑当前模型”从当前模型的**原始导入数据**重新组织流水线，不是从上次已精排的 UV 再填空。希望在当前有效结果上继续挤空间，应使用独立填空按钮。三块折角带、六岛立方体等专门教学示例保留各自的显式初始方案，不被不相容的原样检查配置挡住。

流程配置支持 JSON 导出/导入。版本、布尔值、范围均验证，未知字段不进入任务；损坏/禁止访问的本地存储回到安全默认，仅影响持久保存，不阻塞本次操作。配置示例：

```json
{
  "version": 1,
  "source": "auto",
  "repairInvalid": true,
  "mergeAdjacent": true,
  "fill": true,
  "fillBudgetSeconds": 15,
  "fillRounds": 8
}
```

### 实际步骤，而非动画进度猜测

日志状态为等待、进行中、完成、跳过、失败、取消；显示阶段实际耗时、最后处理详情与跳过原因。事件从生产 Worker 的真实算法入口发出，数字进度不会让尚未开始的阶段提前“完成”。完整阶段列表保留在返回快照中，可导出报告。

流程正在运行时修改草稿，日志仍然显示旧任务的实际配置，明确提示“仅下次生效”。下载下一模型时，上一模型日志明确标为上一计算记录，不会冒充新模型已经完成。任务取消/报错保留同一源模型的上一份完整结果；新模型不继承上一模型的几何结果，旧 Worker 的迟到消息无法覆盖新任务。

这是有依赖的固定顺序流程，不允许将“填空”拖到“求解”之前。原样检查不能同时填空；当前自动填空只支持单页，遇到多页配置明确提示，不无声合页。关闭局部修复意味着遇到无效原岛会明确拒绝，并非允许错误 UV 继续传递。

搜索预算只约束填空搜索，最终几何验证和铰链准备还要时间；整个 UV 任务原有总预算仍生效。请根据模型大小设置总预算，不把“15秒搜索”当成从点击到结束的硬总时长。

## 3. 默认突出效果改为全局上下文半透明

动画工具页默认 **“播放时突出当前岛”**，非活动岛透明度默认18%，可调3%–65%。旧的球形局部散点仍作为明确备选，也受同一播放事件控制；不再默认用球范围挖掉局部前景。

| 当前状态 | 3D 中的显示 |
|---|---|
| 暂停、尚未播放、单次阶段跳转 | 原有选中/未选中显示，不施加临时突出 |
| 播放中：等待岛 | 整个岛临时半透明，而不只处理球内部分 |
| 播放中：正在展开的岛 | 保持实体，包括最后移入 UV 的阶段 |
| 接力重叠段 | 两个实际运动岛都保持实体，前岛必须完整结束才淡化 |
| 播放中：已经完成、位于3D场景UV框中的岛 | 临时半透明，避免挡住下一岛 |
| 按住进度条拖动或按住方向键调进度 | 按当前姿态的运动岛应用同样规则 |
| 松开指针/按键、取消指针、丢失捕获、失焦 | 结束拖动，恢复原显示；不自动恢复播放 |
| 暂停、播放自然结束、反向播放到起点 | 立即撤销临时突出，恢复原先上下文设置 |

恢复不是把所有东西都设成实体：原先选中单岛、未选岛半透明/隐藏/实体的设置保持原值。没有改变显式选择、进度、相机、源几何、最终 UV 或导出结果。程序设置一个中间进度本身不等于拖动事件，不会无限保留半透明。

底层将当前活动岛与其他岛分开绘制；背景面不写深度，当前岛保持不透明。它是检查动画的示意透明效果，不是物理透明材质或全场景排序正确的半透明渲染。复杂重叠可能仍有明暗差异。右侧二维 UV 编辑器不随这个临时效果变透明；处理的是3D场景，包括已经放到UV框里的面片。

仍保留大面积优先队列、0.25×–64×、逐岛接力、静止区间跳过、自由相机、框选及先岛后面的选择机制。运动叠层仍区分投影遮挡与真正几何相交。

## 4. 实际验证

正确资产经生产 Worker 分别运行“标准整理”和“整理＋填空”，四次全部通过：人台18,324面/79岛，头盔94,722面/130岛，源输入不变，完整结果检查有效，导出OBJ再读取岛数一致。填空关闭时没有精排报告，开启时恰好一个填空阶段且在构建对应数据之前。

本轮用于验证步骤的真实模型设置为**3秒填空搜索、3轮、210秒任务预算**，不是新的最佳占用率测试，也不能与上一版90秒精排结果混作同预算比较。具体执行次数、原文件哈希和阶段耗时在 `validation/v0.4.14/real/`。

20项流程策略、14项临时突出策略、16项实际浏览器流程、24项WebGL像素、17项播放/拖动生命周期通过；其他回归与限制见 `VALIDATION.md`。截图是正确人台经真实Worker处理后的离线工作台，不是设计图，也不是完整React主入口认证。

离线单文件 `unfold-lab.html` 可直接打开；受浏览器本地文件限制时用 `node scripts/serve-unfold-lab.mjs`。离线用户入口支持 OBJ/内置例，不将固定夹具解码器冒充通用 GLB/FBX 加载器。

所有变更在原 Git 中小步提交，旧版本 tag 不移动，使用独立附注 `v0.4.14`。源码ZIP包含`.git`及完整恢复bundle；最终ZIP另行重新解压验收。新UV依然需要相应的贴图重烘焙，本版不提供自动烘焙。
