# v0.4.10 · 面积比例、空间邻居与大岛优先的新 atlas

## 本次修复什么，不宣称什么

用户报告 Corset 的98个源UV岛、#1/#75等叠放，以及小3D区域占据很大UV面积。本版确认并改动了实际入口：此前 Extract 直接显示源坐标，绕过已有的新atlas面积归一化；旧后处理只认共享网格边；原排布偏向包围盒长边而非源表面积。**本轮没有成功取得真实Corset/FlightHelmet二进制，不能将下面的合成结果写成这两个资产已修复，更不能给它们编造合并后的岛数。** 公共glTF元数据不足以诊断用户的具体#1/#75。

## 1. “Extract + 整理原 UV”与“原样检查”分开

主按钮现在明确标为 **Extract + 整理原 UV**，不再用“提取”暗示其结果既未经改变又已修好。该路径读取原岛，审计原坐标，默认尝试真实邻边缝合，然后进行面积归一化、空间邻近关联和无岛间叠放排布，返回**新atlas**。主Studio中导入具备完整、有限UV坐标的模型默认采用此路径；没有完整UV的模型仍从生成路径开始。

相邻按钮 **原样检查（不修正 UV）** 保持源值、原裁切和原材质分框，用于比较。原样检查里继续出现重叠或不均匀密度，不是“整理没有运行完”；该按钮本来就不修改资产。新atlas和原输入审计分别标明，不把原审计里的98岛误报为当前结果的岛数。

整理不会覆盖输入顶点、面或原UV。新的UV坐标通常需要重烘焙贴图；本版没有贴图烘焙功能。OBJ导出、2D画布和动画终点引用同一套当前结果，不把仅用于材质分框的平移写入原UV导出。

关闭“整理原 UV 时尝试共享边缝合”可只统一面积和重排，保留岛数。原岛内部若有折叠、混合翻面、自重叠或退化，后处理明确拒绝，不能靠缩放或换位置修好；应使用“前处理：连通优先重分割 + 自动缝合”从3D求解。原样模式仍可查看这类输入。不偷偷用另一算法成功结果替代失败状态。

## 2. 面积按真实表面算，不按轮廓或包围盒猜

对岛i的每个三角面求3D叉积面积，得到 A3D_i；对UV三角形求绝对二维面积得到 AUV_i。归一化采用：

```text
岛内统一线性尺度 s_i = sqrt(A3D_i / AUV_i)
最终UV = 旋转(原UV × s_i × sqrt(b_i)) × S + 排布平移
```

b_i为可选小岛**面积**增益，默认1；S为全图共同线性缩放。默认因此使各岛 `最终UV面积 / 3D面积` 相同，而不是要求以平方米计算的数字与0–1空间数字相等。不分别拉伸U/V，不把岛变成其包围矩形，不通过删面刷面积比例。每个岛内部已有的局部拉伸不会仅靠整体缩放消失。

可选 `tinyIslandAreaFraction` 默认0（关闭），范围0–0.1；`maxTinyAreaBoost` 默认1，范围1–4：

```text
b_i = max(1, min(面积增益上限, 全部3D面积 × 小岛目标占比 / A3D_i))
```

例如目标占比1%、上限2，只允许较小岛最多获得严格等密度结果的2倍面积，等价于最多sqrt(2)倍边长；不是2倍边长/4倍面积。上限是相对未增强的同一公共密度而言，整体S仍可能因装箱改变。目标占比是归一化前的软提升目标，不保证最终UV总面积中的精确百分比。多页使用全体岛面积作为参考，并采用相同的S，不让每页独立填满破坏跨页密度。

选岛检查器显示同UV域的 `3D占比、UV占比、UV占比/3D占比`。比值1意味着平均密度一致；大于2或小于0.5进入偏大/偏小提醒。该提醒不是UV有效性标准。原布局有叠放时，面积总和包含重叠多重计数，不是纹理空间占用率；有效占用率与包围盒占用率另行报告。

## 3. “相近”可以有邻居关系，但不会冒充已连接

新增独立的3D关联图：

| 边类型 | 来源 | 用途 |
|---|---|---|
| shared-edge | 真实共享网格边、兼容面归属 | 优先缝合候选；仍需实际求解/有效性验证 |
| spatial | 表面/边界空间采样接近 | 关联组、同页偏好、排布距离偏好；不创建焊接或UV等式 |

默认距离为导入后模型包围盒最长边的2%；UI可调0–20%。默认每岛最多96个确定性样本（边界和面心），最多4个空间邻居，整个近邻比较最多2,000,000次。API可调每岛8–512样本、1–16邻居。达到比较预算会标 `truncated`，未检出不能证明不存在邻居。采样不是精确三角形最近距离，也不是语义识别；大面内部的小饰物关系可能漏检，较大的距离也可能误把独立但靠近的部件关联。原模型/相机/动画的坐标都不改变。

图边有距离、支持样本和法向连续性分数；原共享边优先级较高。UV空间靠近本身不会成为3D邻接证据。真实岛数与关联组数分别显示；页报告的 `geometryComponents` 和 `associationComponents` 也分开。一个组可以包含多个真正断开的岛，组数减少不等于岛数减少。组的传递闭包也不表示组内任意两岛都直接相邻。

单页排布默认使用软邻近偏好；新“空间邻近 + 共享边优先同页”模式还使用该图分配页面。几何components/adjacency旧模式保留原语义。页数是软目标，不跨完全无关联组件虚构关系；页上限仍64。空间图只给出倾向，不保证所有邻居在最终二维布局中都相邻。

## 4. 大岛先摆，小岛后摆，共同缩放再试

默认按**真实3D表面积降序**放置。小岛增益造成目标面积相同时，仍不改变真实表面积优先级。选项 `packingOrder='legacy'` 可复现原长边/包围盒排序。

预选岛的旋转方向，在保留gutter的前提下尝试装箱；全部岛放不下时缩小公共S，重新尝试全部岛，而非只缩小最后的小岛。MaxRects与大岛数Shelf均接入排序和邻近软代价；诊断记录实际放置顺序、搜索尝试次数、失败试装次数和小岛增益。默认56次搜索尝试（2次确定性排序尝试各28轮），不是连续播放时每帧搜索。

默认超过256岛改用Shelf；显式MaxRects仍有1024岛保护。**仍是包围矩形装箱，不是凹多边形嵌套，也不保证全局最优利用率。** 邻近偏好和更少的岛可能牺牲填充率。极小UV岛可能小于像素；严格面积比例下这不是自动将其放大几百倍的理由，可有界提升或提高纹理分辨率。边距本身占满页面时明确报错，不让岛相交。

## 5. 使用建议与本地真实资产回归

重新打开0.4.10后，先用 **Extract + 整理原 UV**。对比原数据使用 **原样检查**，选中待查岛后查看面积占比与邻居。仍然需要更少岛时，可对当前结果继续真实缝合，或使用连通优先前处理；空间关联不会单独降低真实岛数。

```bash
npm install
npm run dev
# 真实资产必须已下载；不要把失败/跳过计为通过
npm run assets:download -- --only corset
npm run test:sample-asset -- --asset corset --pipeline source-atlas --report corset-atlas.json
npm run test:sample-asset -- --asset flight-helmet --pipeline source-atlas --report helmet-atlas.json
# 对用户正在测试的精确同一文件定位，面/岛编号才有可比性
npm run test:sample-asset -- --file /absolute/path/model.glb --pipeline source-atlas --report actual-atlas.json
```

真实资产脚本增加面积、邻居和放置报告，但本轮没有成功执行该真实GLB路径。两套UI均改动；离线页支持OBJ/内置网格，不伪装支持FBX/GLB。完整React/Vite、FBX导入、真实资产和macOS/Windows实机范围见 `VALIDATION.md`。
