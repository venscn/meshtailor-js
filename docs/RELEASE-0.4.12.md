# v0.4.12 · 大岛优先的迭代填空与轮廓精排

基于真实模型已验证的 v0.4.11（cbf43b6）继续开发，保留旧 Git 历史、全部 tag、正确模型夹具和原来的局部修复／缝合能力。本版主要改变 **已有有效 UV 的空间利用**，没有改变源几何、原 UV、岛归属和裁切线。

## 入口和操作顺序

完整 Studio 与离线工作台均有 `UV → 空白精排 · 大岛优先 → 填补空白（保留当前岛 / 切缝）`。

先用 **Extract + 整理原 UV** 得到有效的单页布局，再点填空。也可以对已整理 OBJ 使用原样检查，然后填空。按钮使用**当前 snapshot**，不会重做 baseline、重新缝合或归一化；再次点击从上次有效结果继续，原样 UV 始终保留。

原样检查中还有岛内折叠、跨岛叠放、越界或不满足所设边距时，会明确拒绝，不能把叠放面积冒充收益。取消或全局超时保留原 snapshot；本地搜索预算到达时，先验证最后一份完整候选，通过才返回。单个失败试装不会污染当前 UV。

## 1. 分离两个目标：填空，以及有上限的面积优先

普通装箱后先尝试轮廓重排和最多3次共同放大，利用整体空白；这部分保持岛间平均面积密度比不变。

之后 **大岛优先** 模式按真实3D三角面面积总和降序：给当前岛增加一小步面积，重新安排它和其后所有较小岛。已经更大的前缀优先保留位置。只有全部岛都能放下，才提交这一小步；失败整次回退。每轮都从大岛开始，无改进时缩小步长，再进行有界尝试。

岛内仅执行旋转、平移、统一缩放，不分别拉伸 U/V。所有小岛面积均不低于本次开始时的值；不能靠压缩小岛去买大岛的清晰度。排序不按包围盒长边，也不按岛ID。

另有 **共同密度** 模式：所有岛使用同一个面积增益。它保持当前已有密度比；不会将此前已经采用不同密度的结果自动归一。严格等密度的新布局应先从面积归一的整理结果开始。

### 面积与边长不是同一倍数

若岛 i 的初始 UV 面积是 U_i、增益是 g_i，精排后面积为 `g_i × U_i`，边长尺度为 `sqrt(g_i)`。

默认每步是 **8%面积**（边长约3.92%），增益上限 **1.6倍面积**（边长约1.265倍），不是边长1.6倍。还限制最大/最小平均面积密度的相对差异：重复点击不会无限叠加“大岛比小岛更密”的差距。输入本来就超过该比值时，不以偷偷缩小岛来强行满足上限，报告输入和输出密度比。

“3D面积大”是本版可解释的优先级启发式，不等于识别了观察视角或重要语义；很大的背面未必比小脸部更重要。本版没有新增手工重要性涂抹或相机可见性估计。

## 2. 真正利用凹口，不再为每个岛预留完整矩形

新精排器是独立 TypeScript 实现，使用保守三角面占用栅格和位集碰撞搜索。三角面碰到的格子都视为占用，而不是只判断像素中心，因此小细节不会无声穿过。凹口和空洞仍为空位，允许其他岛占用；整个包围矩形不再被当成实心。

默认512格，允许128–1024（界面提供256/512/1024）。只搜索当前朝向及90°旋转，不做镜像，也不是连续角度的全局最优多边形嵌套。细栅格能保留更多窄空位，但耗时和内存增大；保守栅格也可能错过实际可行的窄间隙。找不到不缩小的完整试装时，保留基线，不宣称几何上绝对无法装下。

边缘留白沿用现有 padding，岛间至少保留两侧 padding 的间距。最终再对**全部实际 UV 三角形**检查翻面、退化、正面积重叠和边框，失败回退。栅格只用于搜索；填充率来自几何三角面积，不是占用像素数。

岛包围盒允许相互覆盖，所以“包围盒面积总和”可能超过100%；这不表示三角形叠放，也不再标为有效占用率。

## 3. 多轮、预算与停止理由

| 选项 | 默认值 | 说明 |
|---|---:|---|
| 模式 | 大岛优先 | 也可共同密度；没有开启时沿用原装箱。 |
| 面积步长 | 8% | 无改进时可减半。 |
| 面积增益上限 | 1.6倍 | API范围1–3，不是边长倍数。 |
| 调整轮数 | 4 | API范围1–24。 |
| 搜索分辨率 | 512 | 不是输出纹理分辨率。 |
| 搜索时间 | 15秒 | **只约束精排搜索，不包含后续全图验证**。 |
| 尝试预算 | max(128, 岛数×4) | API可明确配置，最高5000。 |

任务原有的整体预算、进度、取消仍生效。停止原因区分：轮数到达、尝试次数耗尽、搜索时间用完、本轮步长无改进、栅格未找到完整布局、最终验证拒绝。预算耗尽不被说成全局收敛。

报告包含实际配置、每次接受的增益、放置顺序、真实占用率、平均面积密度差、停止原因和耗时。每次接受的完整状态都增加有效占用；没有收益则保留旧UV位置，避免仅为“正在优化”而无效挪动。

本阶段优先考虑紧凑性与大岛面积，**可能牺牲原装箱的空间邻居软偏好**，不保证所有相近3D零件继续在2D中紧贴。当前独立填空仅支持有效单页 atlas；多页请求明确报错，旧多页显示/排布在不开启精排时保持原功能。

## 4. 真实 Corset / FlightHelmet 对照

继续使用正确的 `meshtailor-test-models(1).zip` 对应哈希锁定 glTF/bin，不读取旧错误压缩包。生产 source-atlas Worker 完成局部修复、缝合后，按新设置执行精排。

本表测试配置：512格、8%面积步长、1.6面积上限、4轮、最多128次试装、90秒搜索预算、240秒整个任务预算。**不是界面15秒默认搜索的性能承诺。** 两模型本次均在128次试装停止，仍可继续有界尝试，不声称已经填满或全局最优。

耗时是本制作环境的单次记录，非独占机器基准；其他并发检查、CPU、浏览器与GPU会影响它。最终UV导出后重读仍有79/130岛；源顶点、面及面顺序不变。

除了本工程的UV检查器，还对实际导出OBJ用独立GEOS/Shapely的三角形多边形求交复核，检查了117,370/653,573对相交候选（包含普通共享边），正面积重叠为0，最大交集面积0，面积容差 `1e-14 UV²`。报告与OBJ SHA256绑定。Python/Shapely仅用于额外QA，不是JS工程运行依赖。

## 5. 何时考虑重新裁切

报告列出包围盒浪费最多的岛和其形状填充比，便于人工检查长条、深凹和环状岛。但这只是诊断：低利用率也可能来自 padding、密度上限、当前栅格方向或预算，而非裁切线错误。

本版**不为了刷满面积自动增加接缝**。要改变切缝，仍使用独立前处理并与当前版型对照。避免刚将碎岛合并成大块，又在填空阶段无声切回大量碎片。

## 运行与复现

```bash
npm install
npm run dev
# 正确模型已在包内，无需网络再次下载。
npm run test:fill
npm run lab:build
npm run test:fill:browser
npm run test:fill:real -- --out validation/local-fill-real
# 完整Studio还应执行 npm run build / npm run test:browser。
```

离线页：根目录 `unfold-lab.html`，或 `node scripts/serve-unfold-lab.mjs`。支持OBJ与内置例，不冒充GLB/FBX完整入口。截图使用明确标记的凹口合成片，真实模型结果见独立OBJ结果包和上述报告。

真实回归入口使用固定输入解码器 + 生产装配、Worker、几何、UV、导出模块；不是通用 Three.GLTFLoader 端到端测试。完整React/Vite构建本轮仍因 npm DNS/缺少依赖未通过，详见 `VALIDATION.md`。自由相机、逐岛接力、无动作阶段跳过、先岛后面的选择机制均未被替换。

新UV的面积与位置变化通常需要重新烘焙贴图。此版不自动提升已有贴图的信息量，也没有贴图烘焙功能。

参考背景：xatlas也将chart生成与packing分开，并提供padding、旋转、纹素尺度等装箱控制；本版没有依赖其代码、WASM或权重。官方接口 https://github.com/jpcy/xatlas/blob/master/source/xatlas/xatlas.h 。本版搜索和有效性检查为独立JS/TS实现，不宣称与xatlas结果等价。
