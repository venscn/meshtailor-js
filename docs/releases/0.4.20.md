# v0.4.20 · 纯几何自动展 UV 与真实切缝修正

## 输入与目标

基于 v0.4.19 / 2d0bcd98a272a419a8ceae3eed3c80aa2363079b 的现有历史开发，保留旧 tag。生产生成器不使用模型原 UV 坐标、原 UV 索引、由原 UV 得到的切缝／分组，也不在求解失败时恢复原坐标。没有模型名称或固定岛号专用出口。

历史 source-atlas／提示路径的好结果不能当作自动展开能力。现在模型加载、Generate baseline、Runtime 默认方法与 CLI 都从同一几何生成策略开始。

## 1. 隔离源 UV，不只是默认取消勾选

`geometryOnlyMesh` 明确复制位置、三角形顶点索引和对象／材质元数据；不展开整个 face 对象再删除 UV，避免 getter 或额外提示被读取。入口、Worker 传输前以及生成器内部均执行白名单。导入器不把纹理坐标属性装配成内部几何；几何 GLB 删除 TEXCOORD/TANGENT，保留位置、法线、索引、节点与材质标识。

旧 source/source-atlas Worker 请求明确报错；peelSourceHints 在直接底层调用时报错，在统一工厂中固定为 false。原样检查及旧切缝恢复入口从两个工作台移除。v1 浏览器存储迁移只保留填空预算等安全项，不恢复源 UV 模式。

后处理的 UV 来自新生成的当前快照。`inputPolicy` 用于内部流程标识，并非防御恶意外部代码伪造的密码学签名。已知历史 UV 函数和参考文件仍可供离线 QA，但没有生产自动路径调用它们。

真正的原始测试文件只用于哈希身份与三变体测试；生产页自带另外生成的 **无 UV 几何资源**。测试故意改变原 UV，恰是为了验证完全不影响输出，而不是读取它来选切线。

## 2. 真实分割边界，而非 UV 轮廓装饰

旧 baseline 的局部高折角选边／区域法线扩张与通用生成不同，容易得到很多零散切边。新 baseline 不再向另一生成器喂这种碎边，而是直接展示统一生成器最终实际使用的切缝；3D traversal 也从这份结果生成。

连续折角提供有面积门槛的分组证据；不把“大曲面有相反法线”直接等同于必须从两端粗二分。显著平面、凹口、孔洞保留。区域不足以直接展开而需要分界时，在两组边界的窄带内做二元图割：共享边长、折角连续性、移动距离共同决定面归属。硬切缝和内部锚定面不动；接受前检查两个组连通、面积保持、尖齿代理不增加和切边长度。

这改变真实面归属和源网格边切缝。导出的切线、3D边界和UV边界同步变化，源位置、面顺序和三角形集合不变。真正的模型棱角／齿形不作为光滑区域噪声删除。

组内开口路径加入前驱方向状态与转向代价，减少纯最短边路沿三角化交替拐弯。已有孔洞先尝试直接求解；带柄区域可用原始边上的 tree/cotree 切图打开，虚拟盖只用于拓扑搜索，不加入导出几何。

## 3. 求解器不再把自己的缺陷都转成额外碎片

- 投影种子、ARAP结果、LSCM结果统一验证切割边界简单性和三角形有效性。不能以“正面积交叠为零”掩盖切口两侧贴回一起。
- genus 0、合法多边界的曲面可以尝试 LSCM，不再一律因非 disk 被拒绝。圆边界初始化仍只用于适用拓扑，手绘目标不直接交付固定圆边界回退。
- 正规方程使用稀疏 IC(0) 预条件；移位只用于预条件器，原目标方程及残差不被偷改。
- 手绘模式不因长条的包围盒长宽比高就强行切短；仍检查拉伸、面积退化和全局交叠。
- 低面数闭合多面体的两三角形大面可被认作完整平面；开放折角带不因每两面恰好共面就被拆成小面板。这两个反例都有回归。

“尖齿代理”定义为处于光滑邻域、同一三角面两条以上边是内部组分界的局部计数。它可以定位三角化造成的小尖角，但不是人工语义评分，既不保证计数为零，也不保证每个计数都是错误。新模型全部实际切边仍在源网格上；没有重网格以画出与原三角化无关的完美曲线。

## 5. 验证与已知限制

本轮执行输入getter隔离、实际边界图割、投影切口反例、孔洞/带柄开缝、统一策略、真实模型三变体、全图边界/面覆盖/OBJ重读、独立几何求交。浏览器通过实际按钮、UV鼠标点选、RAF播放、无网络真实样例载入；还重跑相机39项、动画到达28项和岛/面选择39项。

历史选择脚本先暴露两个演示回归：纯几何立方体不再自动六片，以及开放折角带被识别成12片。这些不是隐藏失败；已经分别加入闭合多面体／开放带状回归并再次通过，不靠恢复演示原UV绕过。

浏览器新工作台流程14项使用 Chromium 软件WebGL。高面数模型的线框、叠层诊断在软件渲染中很慢，本轮真实头盔页面检查关闭了线框、编号标签和重叠诊断；不宣称各GPU的大模型流畅性认证。核心和Worker为严格TypeScript编译。

完整React/Vite主入口的npm依赖安装在40秒预算内未完成；实际build退出127（缺少vite），typecheck退出2（缺少node类型）。13个TSX语法转译通过不等于React语义类型或Three通用导入器E2E通过。离线工作台支持OBJ和内置无UV模型，完整Studio通用FBX/GLTF入口仍需用户环境安装依赖验证。

这不是MeshTailor官方学习权重，也不是任意对象的人类语义裁片生成器。组/切缝策略仍是启发式，有效性、边界连续和部分轮廓保留不等于所有结果均适合手绘。没有用排布占用率、少岛或三角形误差冒充可识别性评分。新的默认生成结果岛形不同，不能与过去原UV整理或长时间精排的填充率直接比较。
