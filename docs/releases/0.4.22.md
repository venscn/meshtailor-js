# v0.4.22 · 完整部件分组、双侧切线对应与结构片松弛

## 本次范围

在完整 `v0.4.21` Git 仓库上继续，小步提交、旧 tag 保持不变。此前未能保留下来的实验目录不冒充已恢复历史。生产只读几何；模型原 UV、原接缝和原岛标签不参与任何生成决策。原 UV 仅在 `scripts/structure-reference-qa.mjs` 的**生成结束后离线对照**中读取。

本版确实改善了完整护目镜和人台主要衣片，不宣称所有壳体、附件或任意模型都达到人工版型质量。尤其是一般大曲面仍沿用现有通用求解，没有新增语义分类模型。

## 1. 分组正确，也不等于展开形状正确

人台主体从几何上检测稳定镜面、狭长的中部连接区域及其端部，保持两侧连通性，得到 **640 / 640 / 112 面**。这与该区域作者的三组面集合吻合，但算法并不读取这些集合或硬编码面数。

单纯把这三组交给 LSCM，仍可能得到趋近梯形的衣片：共形种子在数值上有效，却让局部区域的尺寸比例改变。本版对这类已验证结构片继续做**基于原3D边长的自由边界 ARAP 松弛**，不以“第一个无重叠结果”立即结束。源面、切线和分组不变；最终仍检查全局边界、三角形交叠及形变。

实测两个640面衣片能量分别由约0.16165/0.16797降到0.02567/0.02560，分别接受46/41步；112面连接片接受34步。能量是本实现的几何误差，不是人工可读性评分。对照图显示实际形状变化，不只报告岛数。默认60次迭代上限；UV工具里可设为0进行对照。被拒绝的松弛不会覆盖有效种子，也不会使用原UV补洞。

## 2. 护目镜必须按完整部件验收

旧版只拿出835面主片，把其余2141面混在一起展开。本版沿几何边流搜索连续闭合候选，**共同评估两个主片、孔壁和背面**的连接、边界环、表面积及对应关系，不再单独挑最大可投影正面。

真实2976面部件得到：

- 两个主片，各 **1008面**，各有一个外边界和两个眼孔。
- 两个完整回折孔壁，各 **480面**，分别用连续开缝打开后展平。
- 所有2976面恰好出现一次。作者参考是656/1440/440/440面；本版没有复制作者的切缝，也不以岛数相同宣称形状完全一致。

当前检测覆盖有清晰几何边流的闭合双孔/三孔厚壳。它不是所有拓扑或无规则三角网格的语义识别器；证据不足时不强制使用这类结构分组。主片和壁片必须**全部**通过末端结构检查；不能保住一张好看的正面就接受其余坏片。面数预算不足或主片求解失败时明确失败，不为了满足求解器把受保护主片递归切碎。用户的上一份完整结果仍由原有任务生命周期保留。

## 3. 对称不再按独立三角形各自判断

对称平面候选使用连续三角面二阶矩，不用顶点采样权重去引入对角线偏差。对应采用有界、相互最近的几何关系；镜像后的三角形若落在另一侧相反对角线的四边区域，则将两侧各两面作为一个对应单元。实际面标签联合更新，再验证连通性、孔数、顶点扇及硬切线；不镜像移动顶点、不重建几何。

| 结构 | 可靠对应面覆盖 | 对应面数 | 异对角线单元 | 已对应区域分组冲突 |
|---|---:|---:|---:|---:|
| 人台主体1392面 | 98.85% | 1376 | 323 | 0 |
| 护目镜2976面 | 82.53% | 2456 | 389 | 0 |

**未对应的人台16面、护目镜520面没有被冒称为对称保证。** 原几何本身和三角化可能不完全对称，不能强制左右面数相等充当质量证明。

两侧回折壁的开缝还使用**反射三维引导曲线**，在目标实际网格边上搜索，不假造缺失边。当前两侧各12条边，镜像后的曲线最大偏离约0.001003源坐标单位，为原切线长度的3.98%。目标边界、切口和盘状拓扑再次验证；距离超过门槛即拒绝。这是近似对应，不是逐点绝对镜像。

## 4. 最终结果、显示及重新排布

默认“手绘轮廓优先＋自动”已接入，不需要新隐藏预设。主 Studio 和离线工作台的 UV 工具页有完整结构分组选项及松弛迭代设置。选中相关岛时，检查器显示主片/回折壁、保留孔数、对应覆盖率、冲突及配对开缝偏差，不将部分覆盖包装成全部对称。

重排和填空沿用当前生成UV，但会再次验证完整主片、壁片、孔数、开缝、逐角一致性及边界简单性。它们不能偷偷重新合并主片与孔壁，或把眼孔并入外轮廓。

| 正确原始资产 | 全部源面 | 最终岛数 | 普通排布有效UV占用 |
|---|---:|---:|---:|
| Corset | 18,324 | 87 | 51.1863% |
| FlightHelmet | 94,722 | 187 | 57.3315% |

这里没有执行长时间精排，不是最高填充率结果。全模型包含其他仍可能难以辨认的片，不能用这两个完整部件的改善替它们全部验收。头盔仍有21个局部尖齿代理计数，人台该计数为0；代理不等于人工语义评分。

## 5. 可复现与实际验证

生产Worker中，两份正确资产各执行原UV、无UV、随机UV三种输入，所有生成切线、面角坐标和OBJ逐字节相同。全部面保留，切边界/孔与逐角一致性通过。独立GEOS/Shapely检查实际导出OBJ，正面积交叠为0，阈值1e-14 UV平方；源3D坐标与面顺序不变。Python只是额外QA，不是运行依赖。

新增测试：12项对应/分组、15项完整结构与尺度/姿态/破坏拒绝、8项结构松弛、13项真实浏览器流程。另有14条原有回归命令全部退出0，具体命令、范围、计时在 `validation/v0.4.22/`。旧单主片测试已明确隔离为 `structureGroups:false` 的底层候选测试，不能拿它代替新默认流程验收。

```bash
npm run test:structure-symmetry
npm run test:complete-structure
npm run test:structure-relax
npm run test:geometry:real -- --out validation/local-real
npm run lab:build
npm run test:complete-structure:browser
npm run results:restore
```

包内对照图比较**同一批3D面**，没有隐藏背面或孔壁。每片单独调整显示方向与尺寸以比较形状，不用小图面积对比纹素密度；实际导出坐标未改动。可用作者UV做离线参照，但生产端不允许从它恢复、分组或初始化。

## 6. 明确限制

完整 React/Vite/通用 Three 导入主入口本轮没有构建通过：安装在25秒预算结束后未获得依赖，build缺Vite、全量typecheck缺Node类型。通过的浏览器测试是实际离线工作台、生产Worker和WebGL，不是伪React或主入口认证。软件GPU上整头盔的诊断绘制仍可能很慢。本版没有macOS/Windows/Safari硬件实测。

没有修改用户相机、播放倍速、时间轴亮显/渐隐、接力顺序、静止跳过、框选和先岛后面的选择规则。UV改变后仍需要相应重绘/烘焙贴图；本版不自动烘焙。
