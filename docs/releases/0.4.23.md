# v0.4.23 · 纵向切线预算修复与真实空洞精排

基于 v0.4.22 的完整 Git 历史继续开发。正确 Corset / FlightHelmet 夹具及所有旧 tag 保留。生成不读取原 UV、原缝、原岛，也不使用固定模型名和岛号选择生产分支。

## 1. 褶皱服装：实际根因不是只缺一个转角权重

在 Medium 的12,288面输入上复现：旧环带模板先用未切开的父块面数，与“单片10,752面”的预算比较，直接返回 `template-face-budget`。本来规划的两张6,144面裁片都满足预算，却没有获得执行机会，随后落到测地二分，出现截图中的曲折边界。

现在先规划纵向分片，再逐片检查预算。Low / Medium 保留两张连续裁片；High 的49,152面在默认单片预算下规划四片。模板报告记录请求片数、实际片数和是否因预算增片，不把预算回退隐藏在一般“成功”里。禁用自动切割时不偷偷加片。

这条修复针对两条边界构成的可验证带状结构，不按 garment 文件名处理。真实切线仍位于源网格边上。旋转、缩放、改对角线、UV getter禁止读取和高中低三档均有回归。没有平滑二维显示线、移动3D顶点或删除小三角形来伪装修复。

## 2. 一般开缝增加全局方向参照

原 `smoothPath` 有局部转角惩罚，但局部平顺不代表全程方向稳定。新搜索比较相同端点的原路径与带弦线走廊代价的路径：只有横向偏离降低至少10%、长度不超过原路径1.08倍、转角代价也未明显变差，才采用方向约束候选。所有段仍在真实表面边上，不能穿孔或直接穿过物体内部。

这不是“所有曲面都切成三维直线”。弯管、回折表面以及明确特征边上的合理路径可以是曲线；无法满足条件的候选保留原路径。此处与上一版完整主片/孔壁、镜像对应及硬切缝约束共存，不替代它们。

## 3. 填空：明确修正之前过度简化的解释

旧版填空已经使用实际轮廓栅格，不是把所有包围框涂成实心。旧 `find()` 在固定旋转和栅格下也是穷举扫描，不能说它会无缘无故跳过每一个可行空位。

真正调整的内容是：此前只接受面积增长，不能保留有用的等面积搬移；方向候选过早接受直角结果；前方固定布局约束后续试装；增加连续增长后，自动尝试预算仍按旧次数分配会提前耗尽。

### 空洞候选与完整检查

每轮对真实轮廓和留白生成的占用网格提取空矩形候选。最大空矩形用直方图法完整计算，其他有限候选覆盖孔内、凹口和边角。候选只是搜索入口，不将岛包围框当作实心：找不到矩形匹配时仍回到完整轮廓平移搜索。

先尝试当前位置增长，再试空洞定向位置，必要时重排较小岛及有界的前方大岛。所有配置的补充角度都参与竞争，不再因为一个90°候选成功就提前忽略其余角度。

增加可接受的**等面积搬移**：保持每个岛当前尺度，完整搬移后只有最大剩余空矩形确实变小时才接受。随后继续增长。后续布局变化时允许同一岛一次有界复访，而不是第一次移动后永久锁死。每次最多24次这种中性搬移，每岛最多两次，不无限来回挪动。

**仅搬移不能提高真实 UV 面积占用率。** 报告单独标明 `positionOnly`、空洞定向放置、搬移数和最大空矩形，绝不把空白重新分布伪装成面积收益。

### 多轮增长与预算

按真实3D表面积从大到小；默认每岛每轮可连续增长4小步。失败后降低该岛自己的步长，并立即转向下一岛；达到上限也不阻塞小岛。单次面积步长仍为8%，不是边长8%。

自动尝试预算现在与岛数、轮数和连续增长步数共同计算，最高5000；明确填写的预算仍严格遵守。搜索时间耗尽、次数耗尽、轮数结束、最小步长下无改进分别报告。时间预算到达后验证最后一份完整状态；全局取消仍退出，不返回半张 atlas。

加速后的位集搜索只跳过由真实碰撞证明不可能的连续横向区间；400个随机含间隔/32位边界的窗口，与朴素穷举的首个解逐项一致。未用近似抽样代替找空位。

最终仍逐三角形验证翻面、退化、正面积交叠和边框。只允许旋转、平移、统一尺度；不缩小其他岛购买当前岛的面积，不分别拉伸U/V，不改变本次分割或用原 UV 恢复。

## 4. 入口

UV工具页：默认启用“扫描真实空洞，允许等面积搬移后继续扩张”，连续增长步数默认4，可设置1–16。新参数同时接入完整 Studio 与离线工作台、独立填空与自动“整理＋填空”。修改设置不会重置当前模型、相机、动画或正在运行的任务。

浏览器旧流程不被强制覆盖。要自动填空，选择“整理＋填空”；已有结果需要按新算法重跑，不会因打开新版页面就被悄悄改变。

## 5. 真实测试与边界

详见 `validation/v0.4.23/SUMMARY.md`。对褶皱服装、齿轮、正确人台/头盔分别执行生产生成及精排；前两者为Medium网格，后两者为哈希锁定真实二进制。另实际运行“生成＋共享边后缝合＋自动填空”，不是只测独立函数。

普通生成没有开启后缝合时，人台87岛、头盔187岛；开启后缝合的流程得到86/148岛。两者参数不同，不能混成一组对照。相机、统一动画时间的落位渐隐、先岛后面、框选、逐岛面积顺序未被本次替换。

### 没有声称已解决的部分

- 不能保证所有剩余空白都能被当前裁片填满。齿轮当前只有六片，其中两个大环、两条长带约束可用布局；没有为了消除截图中的空白，偷偷改切缝或把小件缩小。与旧精排相比，齿轮有效占用提升不大，结果表如实列出。
- 最小步长下无改进只是本次网格、角度、密度与搜索策略的结论，不是全局最优证明。空白也可能是形状、边距、倍率上限或预算造成。
- 最大空矩形是带留白的保守栅格指标，不是实际总空白面积；不能拿它减少多少当成同等 UV 面积增加。
- 没有宣布任意人台/头盔曲面都具备人工语义版型质量。两份真实模型的非填空生成与原UV/删除UV/随机UV三变体保持一致。
- 完整 React/Vite/通用 Three 导入入口仍未在本环境构建通过；实际浏览器测试使用同一生产 Worker/WebGL 的离线工作台。未做 macOS/Windows/Safari 实机认证。

## 6. 源码与复现

`human-templates.ts`：先规划再按片预算；`topology-slits.ts`：带方向候选的真实边开缝；`cavity-search.ts`：空白窗口；`shape-raster.ts`：保持穷举语义的区间跳过；`fill-refinement.ts`：中性搬移、候选方向与多步迭代。无需新增运行依赖。

```bash
npm run test:longitudinal-budget
npm run test:raster-window
npm run test:cavity-fill
npm run test:cavity-load
npm run test:seams-fill:real -- --out validation/local-four-models
npm run test:geometry:real -- --out validation/local-uv-invariance
npm run lab:build
npm run test:cavity-fill:browser
npm run results:restore
```

参考OBJ为本轮实际输出，压缩存储一次并带SHA256，恢复不重新求解。导入本工具会重新生成；使用外部UV编辑器查看精确对照。改变UV后需要相应重绘或烘焙，本版没有自动烘焙功能。
