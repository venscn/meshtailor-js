# v0.4.29 · 完整环带优先，端面与整圈侧边分别展开

本版从原 v0.4.28 Git HEAD 继续维护。针对本次 Corset 两张截图，分别复现了真实分区，不将两种原因笼统归为“物体必须切开”。不读取原 UV、原 UV 索引、源切缝或原岛提示。

## 一、图1：不是把圆盘切成两个半圆，而是薄侧边被两张端面各吞了一半

同一完整底座共192面。旧的闭合对称片路径以法线朝向分配两面，得到了96/96面的两个片。端面之间接近垂直的侧面法线点积接近零，法线符号划分把整圈薄边分到了两个片里。

新流程在这类明确的闭合结构中先识别 **端面 / 连续侧边 / 另一端面**，沿真实强折角边环分开。底座得到72/72面的两张完整端面与48面的完整侧边。两端面包含本来属于各自面的倒角；侧边沿一条真实网格边开口，展开成一整条，而不是两张圆片各带半圈。

这是为本结构选择的可解释版型，不是说闭合物体在数学上只能这样划分，也不是把所有整体都强行变成一个岛。两张完整端面与整条侧边各司其职，比追求更少岛数优先。

### 几何判据与保护

候选必须来自完整闭合、流形、零亏格结构；端面是完整连通且可投影为有效盘的面集合；环边是完整两边界环带。两条分界的大部分长度必须落在真实强折角上。平滑球壳不会仅因法线朝向被套用这种规则，带孔齿轮面也不按实心端面处理。

生产规划还设置整体面积证据门槛，避免小纽扣都被无条件分成三片。显式已有切缝不会被此规划删除。后续缝合、重排和填空重新验证实际面归属、完整侧边、真实切口与二维边界；不能再次把侧边混入端面。

**侧边非常细是模型本身的比例。** 此48面侧边的真实展开长宽比约234.765:1，最大局部方向拉伸比约1.002862。UV编辑器内它会很细，这是长宽与表面积约束的结果，不再把它吞回两个圆片，也不为了显眼而单独拉伸宽度。统一/有界面积缩放仍由既有排布设置控制。

## 二、图2：固定“两片”默认值制造了不必要的第二条开缝

两侧对应的完整肩部环状面，各自288面、两个边界环。旧 `humanTemplates.panels=2` 对每件预先分成两份144面区域，不是实际求解已经证明必须再切。

现在 `humanTemplates.panels='auto'` 为默认：

1. 保持原三维面组完整，先尝试一条真实开口缝，求一张完整UV。
2. 完整候选通过实际三角形、边界、形变和每岛面数预算检查后，直接接受。
3. 单片不满足质量要求时，才有理由尝试两片，并记录首个候选的拒绝原因。显式保护缝不会被此重试删除。
4. 每岛面数预算确实不足时，可以增加有规则的纵向分片，报告单片预算原因，不能把“预算不足”说成几何不可展开。

两个肩部环状面的整片方案均通过。每件保留288面，仅新增一条9边组成的真实开口路径，最终各1岛。原有宽度变化保留为完整的开口弧带，不强制拉成矩形。整片允许的局部形变比两片略大：示例一侧最大方向拉伸比约1.982（旧两片约1.687），这是减少接缝与形变间的取舍，不是无拉伸展开。

初次空间分组也先标记符合条件的完整两边界环带，不让通用折角区域把同一环带过早拆散。该逻辑依靠几何边界与轴向可解释性，不依赖部件名或固定编号。

## 三、界面与使用

`UV → 结构模板 · 人工切缝思路`：

- **环带片数：自动 · 完整一片优先**（默认）。可主动选择一片或两片；明确选择两片时仍执行两片，不假装忽略用户要求。
- **完整侧边独立展开，不混入端面**（默认开启）。关掉它可对照先前的闭合片策略；不会关闭其他既有的对称规则。

改变设置不会立刻覆盖当前结果；重新载入模型、Generate baseline或按当前流程重跑后生效。检查器显示本次真实决策、完整面数、岛数、实际开口边数与单片/预算/显式两片原因，不用“像一个整体”代替实际诊断。

相机、倍速、接力、落位渐隐、两级选择和框选保留。生成结果、动画终点与导出引用同一份坐标。再次导入结果OBJ会按纯几何政策重新生成；查看不变对照需外部UV查看器。

## 四、真实结果与诚实的代价

同一份正确哈希锁定模型（不使用以前错误ZIP）：

| 路径 | 旧v0.4.28 | 本版 | 全部面 |
|---|---:|---:|---:|
| 默认生成，无后缝合：Corset | 84岛 | 81岛 | 18,324 |
| 截图类似配置，开启共享边后缝合：Corset | 83岛 | 80岛 | 18,324 |
| 默认生成，无后缝合：FlightHelmet | 191岛 | 191岛 | 94,722 |

图1的底座是2岛→3岛；图2每件是2岛→1岛。不要把总岛数变化当成全部部件的质量评分。内置Low齿轮因内侧环带改为完整一片，6岛→5岛，两个完整齿形和中心孔继续作为平面特征保留。

普通矩形装箱、未额外填空：Corset有效占用率51.0402%，FlightHelmet47.2751%。旧默认为59.9030%/53.1433%；完整长条与更少切缝让当前装箱更困难，**本版没有改进填空算法，也没有隐藏占用率下降**。可以在保持形状的前提下另行填空，但没有声称充分精排后的最优收益。尤其长宽比235:1的完整细边可能限制整张图的共同缩放。

原UV/无UV/随机UV六条整模生产Worker路径的切线、面角UV及OBJ分别一致，全部面和面序保留；导出后独立GEOS/Shapely求交未发现正面积重叠（阈值1e-14 UV²）。原参考生成OBJ只用于三维坐标及面序不变的QA，未作为生产输入。Python是额外QA工具，不是应用运行依赖。
