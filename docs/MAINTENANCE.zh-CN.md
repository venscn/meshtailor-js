# 持续维护

[English](MAINTENANCE.md) | **简体中文**

遵循 [AGENTS.md](../AGENTS.md) 与 [Git 工作流](GIT_WORKFLOW.zh-CN.md)。用户批准具体上传前，维护仅在本地进行。以前的周期授权、定时器、测试通过、合并到 develop 都不构成 push 授权。

## 每个审计周期

1. 检查工作区、当前分支、近期提交、活跃任务分支和待处理批次。保留用户修改；调用目录被占用时使用独立 worktree。
2. 对照真实实现和文档，审计失效/重复代码、过时说明、语义冲突、模块依赖声明、本地化、昼夜主题、响应布局与动态 resize。历史试验与生产验收明确分类。
3. 只记录有行动价值的问题：证据、优先级、影响、复现、文件和有意义的验收目标。重新核对旧问题，避免重复；不确定内容明确标注。
4. 只有职责、根因或必要依赖相同的问题才合批。独立批次使用独立 feature/fix 分支；先处理正确性和必需功能不可访问的问题，再做外观整理。不要为减少分支数强行合批。
5. 实施边界明确的修复，每个完整且验证过的步骤及时提交。验证真实契约或回归，复用已有有效覆盖，避免只复写实现的测试。
6. 审查组合结果，按需将已验证工作本地集成到 develop，记录完成项、检查与剩余限制。main、远端分支和发布 tag 保持不变。

若无可处理问题，不做推测性清理、不建空分支、不重复写报告，等待下一周期。定时运行在无实质变化时保持安静；只报告完成批次、新的重要发现、失败或需要用户决定的事项。周期由 Codex 自动化控制，不在应用内实现后台循环。

## 问题记录

按维护者选择，当前对话的自动化每天 **Asia/Shanghai 上午 09:00** 执行审计与本地开发，未经确认不上传。定时执行需要此 Codex 环境可用；它不是已部署的服务，也不是应用内定时器。

有实质结果时使用 `docs/audits/YYYY-MM-DD.md`。每项包含稳定编号、优先级、证据、状态、负责分支、合批理由、验证和剩余限制。历史检查点或已经完成的 feature 分支不因 ref 仍存在而成为活跃任务。

P0：数据丢失、安全或核心契约破坏；P1：必需功能不可用、正确性问题；P2：可维护性或误导文档；P3：可选细节。优先级不扩大授权范围，也不允许更改远端状态。

## 模块要求

用户明确确认本项目不需要 HTTP 后端和运维端。保持 Studio 客户端、离线工作台、CLI 与共享领域包职责分离，不为通用架构规则添加服务器、运维页面或空壳目录。若未来明确引入服务，再通过清晰契约分离相应职责。共享展示工具负责本地化/主题策略，不让纯几何模块依赖 React、DOM 或 HTTP。

面向用户的模块须支持英文/简体中文、白天/黑夜主题、窄屏/短屏及同一运行页面的动态 resize；诊断信息和绘制视图也属于验收范围。偏好不得改变生成输入、切缝或面角坐标。架构文档描述已实现能力，未来工作明确标注。
