# v0.4.11 · 正确上传模型的真实回归与局部 UV 修复

## 唯一输入与复现范围

本版只使用用户确认的 **`meshtailor-test-models(1).zip`**（2,763,968 字节），SHA256：

```text
284decae81fda986f3c291bf4bebee473221b4eabe7078c65ed44adaf9ffb563
```

旧的 `meshtailor-test-models.zip` 被排除，不读取、不回退、不参与数字对照。四个 glTF/bin 的独立哈希写在 `scripts/lib/verified-model-fixtures.mjs` 和 `validation/v0.4.11/input-provenance.json`；任一不符立即拒绝。旧版本曾未取得二进制的说明是历史限制，不适用于本版的真实几何验证。

测试确实解析了本次上传的 glTF 和 bin，使用生产 `assembleMeshParts`、UV Worker、参数化、排布、导出和 WebGL 模块。为了不把 npm 安装失败伪装成 Three 测试，新增解码器仅接受这两个哈希锁定的静态、无压缩 fixture 格式；**不是通用 glTF 导入器，不是 GLTFLoader 的模拟实现，也不代表完整 React/Three 入口已通过**。用户自己的其他 glTF 仍走正常 Studio 导入器。

## 1. 确认的旧问题

| 正确资产 | 三角面 | 导入后几何连通块 | 原 UV 岛 | 导致旧整理整次失败的原岛（1起始） |
|---|---:|---:|---:|---|
| Corset 服装人台 | 18,324 | 75 | 98 | #72、#73 |
| FlightHelmet 飞行头盔 | 94,722 | 85 | 237 | #6、#12 |

四个原岛同时包含混合绕序和岛内正面积交叠，不能靠重新装箱修正。v0.4.10 的后处理在第一次遇到它们时就拒绝整次操作，未进入后续面积归一与缝合。这不是材质分框、旋转相机或调一个分割角度能解决的。

这些检测结论是针对新建单射 UV 的有效性要求，**不据此断言原作者的贴图复用一定是错误**。原样检查仍允许查看原坐标，不会覆盖它们。

人台原 #1 的真实 3D 面积占比约 **0.251668%**，累计绝对 UV 面积占比约 **4.479528%**，平均密度比约 **17.79938**。这里分母包含原 UV 的重叠多重计数，不能当成纹理占用率；它用于确认“原 UV 面积分配与 3D 表面积不成比例”。新 atlas 则按用户要求统一平均面积密度。

两模型的默认 Boundary 导入都没有找到需补接的微小边界对（均为0），也没有丢弃退化面（均为0）。因此，这一次不能继续用“微小断缝”解释全部碎片。原 glTF 因渲染属性拆分的精确重合顶点，仍按原有每对象精确焊接流程处理；源二进制没有被改写。

## 2. 组合解决流程

```text
原 UV 岛审计
  → 保留有效原岛；仅重解无效原岛
  → 优先真实共享边候选
  → 尝试完整边界缝合
  → 必要时保留开缝，沿合法边界链连接
  → 求解失败时尝试保留已有 UV 形状的相似变换缝合
  → 全量 UV 有效性与形变检查
  → 按真实 3D 表面积统一平均密度
  → 大岛优先、空间邻居软偏好、共同缩放装箱
  → 原图 / 新图分开，导出与动画引用同一份结果
```

### 局部修复，而非把整个模型再次切碎

`Extract + 整理原 UV` 默认开启 **局部修复无效原 UV**。每个无效岛使用原来的完整面集合重建切割拓扑并参数化，必要时允许不拆岛的真实开缝。四个问题岛均能单独修复，不需要细分或删面。

原岛 #72/#73 修复通过后，其他96个人台原岛不重新参数化；头盔则保留其他235个原岛。这是进入缝合之前的保留数，后续接受的缝合仍可能重解涉及的邻岛。修复失败、超时或取消仍整次失败，不返回冒充完整结果的半张 atlas。关闭该选项可恢复严格拒绝，用于对照。

### 合并时不再删除整圈共同裁切

某些邻岛共同边界形成环。把整圈接缝全部删除，可能得到闭合/非盘状区域，造成旧算法拒绝本来可以局部连接的岛。新增边界链尝试：沿真正共享的一段边界连接，保留必要开缝，并重新验证合法切割拓扑与 UV。

保留下来的线是真实的最终 UV 裁切，参与导出；不是紫色动画临时断边。新报告统计 `partialJoins`，不会只把两个包围盒靠近便算一次合并。

### 保留已有形状的缝合补充路径

联合参数化失败时，沿实际共享边对两个有效 UV 岛作**旋转、平移、统一尺度**对齐，不对 U/V 分别压扁。默认限制对齐所需的两岛平均面积密度差不超过 **1.25 倍**（API可配置1–2），再检查盘状拓扑、接缝顶点一致性、所有三角形交叠/翻面/退化及原有形变限制。只有通过后才提交。

它不是对不相连物体凭空搭桥，不降低形变质量门槛，也不保证所有候选可缝合。岛内不同子区域原有的局部拉伸仍可能存在；“每岛平均密度一致”不等于每个三角面完全等面积。

### 自动尝试预算

默认预算改为 `min(512, max(128, 初始岛数 × 3))`，空白输入表示自动；填写数字后严格使用用户的值。达到预算单独报告，不称为拓扑不可合并。保持用户锁定接缝、材质保护选项、单岛面数限制及取消/时间预算。

## 3. 正确真实模型的结果

默认 `source-atlas` 整理，单页、未额外放大小岛：

| 指标 | Corset | FlightHelmet |
|---|---:|---:|
| 原 UV 岛 | 98 | 237 |
| 局部修复原岛 | 2 | 2 |
| 最终真实岛 | **79** | **130** |
| 接受的真实缝合 | 19 | 107 |
| 其中保留必要开缝连接 | 4 | 4 |
| 其中保留形状的相似变换缝合 | 0 | 6 |
| 空间关联组（不是岛数） | 9 | 7 |
| 新图有效三角形面积占用 | 66.9154% | 62.4867% |
| 全图翻面 / 退化 / 正面积交叠 | **0 / 0 / 0** | **0 / 0 / 0** |
| 导出再读取的面数 / 岛数 | 18,324 / 79 | 94,722 / 130 |

新图平均密度比例均在1的浮点误差附近，关闭小岛提升时最大偏差小于 `1e-12`。仅统计包围盒填充率不能代替这些指标。有效占用率已由全图 UV 三角形检查再次计算，不是把源 UV 的重叠面积相加充当填充率。

**没有保证全局最少岛数。** 本身断开的75/85个几何块，不能在不改变几何或不混淆“组与岛”的前提下简单删接缝变成几张连续皮肤。空间邻居关系仍用于关联与排布；它不会改变真实岛数。更少的岛也不必然比原作者的版型更好，相关最大形变仍保留在报告中。

从原3D完全重分割是一条独立策略，不保证比保留有效源 UV 再修复/合并更好；本轮两个模型的默认推荐是源 UV 局部修复＋后处理，而非盲目全局重切。大岛优先、受限小岛提升、邻接图与共同缩放沿用已有实现，本次重点是让真实资产能实际走完整条流程。

## 4. 操作与复现

完整 Studio：`npm install` 后 `npm run dev`，确认 **0.4.11**。重新导入正确模型，使用 **Extract + 整理原 UV**。默认勾选局部修复、整理时缝合和保留形状缝合，尝试预算保持空白自动。原样检查仍会恢复原98/237岛及原重叠；这不是新结果被覆盖或修复失效。

直接查看交付的 `Corset-organized.obj`、`FlightHelmet-organized.obj` 时，先使用 **原样检查**，以查看提供的已整理 UV，避免再次处理改变编号。`*-original.obj` 是从生产导入后的网格导出的对照（已应用 glTF 节点变换及原有每对象焊接），不是原始 bin 的替代物；原始 glTF/bin 请保留。

只测试正确上传资产，不需要 npm 下载模型：

```bash
# <模型目录> 下直接有 Corset/ 与 FlightHelmet/。
# npm依赖不齐时，这两条需要本机已有 Node22.16+、TypeScript；浏览器测试还需 Chrome。
npm run test:verified-models -- --models "<模型目录>" --out "validation/local-real" --export
npm run lab:build
npm run test:verified-models:browser -- --models "<模型目录>" --out "validation/local-browser"
```

新图一般需要重烘焙贴图。OBJ 保留几何、UV与材质域标签，不附原材质贴图、不自动执行贴图烘焙。源 UV 不被修改。离线页仍支持OBJ，不假装支持通用GLB/FBX；完整入口维持原有React/Three架构。

## 5. 验证边界

本版已验证真实二进制、生产拓扑/UV Worker、整图有效性、面积归一及OBJ重读，不再把合成样例当作真实模型通过。浏览器与构建的具体范围、阶段耗时和未通过项见 `VALIDATION.md` 与 `validation/v0.4.11/`。

没有实现语义附件识别、离散壳层的真实几何桥接、凹多边形全局最优嵌套或官方学习模型。没有改动用户相机、动画顺序、静止跳过、两级选择规则或铰链路径以掩盖 UV 问题。
